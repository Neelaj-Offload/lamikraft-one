# Parallel work: lanes, ownership and resource limits

Status: frozen in Slice 0. Implements `docs/PLAN.md` canonical contract 12 and the Execution method.
Machine: Windows 11, 12 logical CPUs, 15.7 GB RAM, Docker Desktop VM 8.1 GB, C: 87 % full, D: ~216 GB free.

---

## 1. Roles

- **Integrator** (the main coding session): owns `main`, Slice 0, the contracts in `docs/architecture/*`,
  merges, lockfiles, generated API types, `docs/*`, `next build`, Playwright, screenshots and commits.
  One local commit per verified slice; never push.
- **Lane**: a parallel coding agent with an explicit path assignment. A lane implements against frozen
  contracts, runs its module unit/integration/contract tests and `npm run check`, and reports. Lanes never run
  Playwright or `next build`, never commit, and never edit files outside their paths.
- **Review agents**: read-only adversarial review per lane diff (correctness, security/IDOR, spec conformance).

## 2. Two working modes

| Mode | When | Isolation |
|---|---|---|
| Shared tree | Slice 0 only (the current checkpoint): disjoint path assignments in `D:\Lamikraft ERP` | no git state changes by lanes (no commit, checkout, reset, stash, rebase); no lockfile or root `package.json` edits |
| Worktrees | Slices 1–6 | each lane in `D:\lk-wt\<lane>` (short path, no spaces) on its own branch, its own env slot (§6); lanes rebase after every integrator merge |

## 4. Single-owner shared files (integrator only)

- `docs/BUILD_STATE.md`, `docs/PARITY_MATRIX.md`, `docs/DECISIONS.md`, `docs/architecture/*`, `docs/EVENTS.md`

Lanes that need a dependency list it in their report (`docs/lanes/<lane>.md` → "Dependencies requested") with
package, exact version, reason and licence; the integrator updates the lockfile.

|---|---|---|---|---|---|
| 0 (main, integrator) | 3000 | 8000 | 3100 / 8100 | `lk_wt0`, `lk_wt0_tpl` | `backend/var/storage` (worktree-local) |

All slots share one Postgres 17 container (`docker-compose.yml`, `127.0.0.1:54329`, roles `lk_owner` and `lk_app`).
Hosts are always `127.0.0.1`. Spawning uses argument arrays (never shell strings) because the main repo path
contains a space; process trees are killed with `taskkill /T`.

## 7. Alembic: one linear chain

- A lane writes its revision locally as `NNNN_<module>_<slug>.py` with a placeholder number. On rebase,
  `lk db reparent` sets its `down_revision` to the integrator's head and renumbers. NNNN is final only at merge.
- `alembic heads` must return exactly one head; checked in `npm run check`.
- Merged revisions are never edited. The integrator may squash per module before the end of Slice 2.
- RLS, triggers (append-only, immutability, product_key guard) and CHECK constraints come only from migration
  helpers; autogenerate output is reviewed for these omissions. A contract test compares `pg_policies` and
  `pg_trigger` with model flags.

## 8. Generated types and API changes

1. A backend lane changes schemas/routes and runs its tests.
2. The integrator merges in dependency order, runs `npm run api:generate`, commits the generated files with the merge.
3. The web lane rebases and builds against the regenerated `schema.d.ts`. Exports are deterministic (sorted keys,
   stable operationIds `<module>_<verb>_<noun>`), so regeneration is reproducible.

## 9. Resource limits

| Component | Approx. memory |
|---|---|
| Docker Desktop VM (Postgres 17) | up to 8.1 GB configured |
| `next dev` (Turbopack) | 1–1.5 GB |
| `next build` | 2–3 GB peak |
| uvicorn + worker | ~0.3 GB |
| Playwright Chromium per worker | ~0.3 GB |
| agent process | 0.3–0.5 GB |

Rules:
- **At most 3 concurrent lanes plus the integrator.**
- **Only the integrator runs Playwright and `next build`**, with `workers: 2`, guarded by the lock file
  `backend/var/e2e.lock` (created and removed by `scripts/dev.mjs test-e2e`).
- Lanes run module unit, integration and contract tests plus `npm run check` only.
- Concurrency tests use explicit barriers, never timing assumptions, so they stay stable under load.
- C: drive: Docker's WSL VHD lives on C:. Keep images to `postgres:17-alpine` (and the optional cached MinIO
  image for the `s3` compose profile), prune dangling volumes after slices, and write backups and dumps to D:
  (`backend/var/backups`). Changing `.wslconfig` or Docker settings is a user decision; agents never change it.

## 10. Merge protocol (per wave)

1. Lanes finish, write `docs/lanes/<lane>.md`, and stop.
2. Review agents read each lane diff (correctness, security/IDOR, spec conformance); lanes fix findings.
3. Integrator merges in dependency order (platform → domain → agents/web), runs `lk db reparent`,
   `npm run api:generate`, `npm run check`, `npm run test:api`, then `npm run test:e2e` and desktop/phone screenshots.
4. A verification pass runs each exit scenario of the slice.
5. Integrator updates `docs/BUILD_STATE.md`, `docs/PARITY_MATRIX.md`, `docs/DECISIONS.md` and makes the slice commit.

Bounded retries: after three failed attempts at the same thing, record the cause in BUILD_STATE and move to the next
unblocked work.

## 11. Contract change protocol

Changes to permissions, events, API conventions, UoW primitives, fixture keys or module ownership are an
integrator PR to `docs/architecture/*` plus the matching code, merged first; lanes rebase before using them.
A lane that finds a contract gap records it in its report under "Contract questions" and continues with work that
does not depend on the answer.
