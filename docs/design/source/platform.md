# Platform foundation: Lamikraft One

## 0. Principles
- Modular monolith with three layers: `app/core` (infrastructure only, no tables), `app/platform/*` (kernel modules that own tables) and `app/modules/*` (domain modules). Imports only go downward. An architecture test enforces this.
- Every HTTP request, agent tool call, job and CLI command runs as a server-built `ActorContext`. Each command runs in exactly one unit of work (UoW). Tenant reads go only through scoped repositories. All output goes through redacting DTOs.
- Fail closed. If the tenant GUC is missing, queries return zero rows. Unknown permissions are denied. A route without an authz declaration stops the app from starting.

## 2. Database conventions
- **Target:** PostgreSQL 16 baseline. Do not use features that only exist in PG17/18. The `pg_trgm` migration is conditional: if the extension is missing, skip the trigram indexes and keep plain ILIKE search.
- **Roles:** `lk_owner` runs migrations. `lk_app` is the runtime role: not superuser, no BYPASSRLS, no DDL. Role settings: `statement_timeout=30s`, `idle_in_transaction_session_timeout=60s`. `lk db ensure-roles` creates both roles.
- **IDs:** `id uuid PK` holding a UUIDv7 generated by `core/ids.uuid7()` (RFC 9562). Business keys are separate, immutable and unique within the company.
- **Mixins:** `TenantMixin(company_id NOT NULL)`, `BranchMixin`, `ActorStamp(created_by, updated_by -> app_user)`, `Timestamps(created_at, updated_at timestamptz DEFAULT now())`, `Versioned(version int, SQLAlchemy version_id_col)`, `Archivable(archived_at, archived_by)`, `Owned(owner_user_id)`.
- **Stamping:** a `before_flush` hook fills `company_id` and `created_by`/`updated_by` from the session's ActorContext. It raises if a supplied `company_id` does not match the context.
- **Tenant foreign keys are composite.** Every tenant table has `UNIQUE(company_id, id)`, and child tables reference `(company_id, parent_id)`. A row in company A can never point at a row in company B.
- **Row-level security** on every tenant table: `ENABLE` + `FORCE`, with policy `USING/WITH CHECK (company_id = NULLIF(current_setting('app.company_id', true), '')::uuid)`. The `NULLIF` is needed because a custom GUC reads back as `''` after a transaction-local set ends.
  - The UoW runs `set_config('app.company_id', …, true)` and `set_config('app.user_id', …, true)` at transaction start.
  - Platform-internal tables are exempt from RLS and are touched only by platform code, always with explicit filters: `app_user, auth_session, auth_attempt, rate_limit_counter, password_reset, mfa_*, permission, job*, worker_heartbeat, domain_event, backup_run, company`.
  - A SECURITY DEFINER function `lk_user_companies(user_id)` lets login find a user's companies without a tenant context.
- **Money:** `<name>_amount NUMERIC(18,4)` + `<name>_currency CHAR(3)`, with a CHECK that both are null or both are set and that currency matches `^[A-Z]{3}$`. Enabled currencies are validated by the app (INR, EUR, USD, GBP). JSON carries `{amount: "decimal-string", currency}`.
- **Quantities:** `NUMERIC(18,6)` + `uom_code`.
- **Enums:** varchar + CHECK generated from a Python StrEnum. No native PG enums.
- **JSONB:** only through `JsonModel[T]`, which validates on write. Use it for snapshots and flexible specs only.
- **Time:** sessions use `TimeZone=UTC`. Local business dates are `date` columns computed in the resolved zone.
- **Engine:** `hide_parameters=True` so logs never carry bound values.
- **Lists:** filters are applied before `LIMIT/OFFSET`. `Page[T]{items,total,limit,offset}`, max limit 200. Feeds use keyset cursors.
- **Concurrency:** optimistic locking via a body `version` field, returning 409 `version_conflict` with the current representation. Locks and constraints protect counters and stock.

## 4. Identity and authentication
**Server-side opaque sessions instead of JWT.**
- The token is 256-bit (`secrets.token_urlsafe(32)`). Only its SHA-256 is stored.
- Cookie: `__Host-lk_session` in production (`lk_session` on http://localhost dev), HttpOnly, Secure, SameSite=Lax, Path=/, Max-Age = absolute lifetime.
- Defaults: idle 12 h, absolute 7 days, recent-auth window 10 min. All are configurable within bounds via `security.session`.
- `last_seen_at` is written at most once per minute.
- The token rotates on login completion, MFA verification and password change.
- Revocation takes effect on the next request.
- Topology is same-origin: Next.js rewrites in dev, a reverse proxy in production. There is no CORS, and startup rejects a wildcard origin.

**CSRF**
- SameSite=Lax.
- Every unsafe method must carry an `X-CSRF-Token` header matching the session's CSRF secret. The value is delivered in a non-HttpOnly `lk_csrf` cookie and checked against `csrf_hash`.
- Unsafe methods must also have an Origin/Referer in `LK_PUBLIC_ORIGIN`. Login has no session yet, so it relies on the Origin check alone.

**Tokens never come from URLs.** The backend ignores `?auth=` and `?token=`. Downloads authenticate with the cookie. Invitation, reset and demo links put their token in the URL fragment (`/invite#t=…`). The page reads it, removes it with `history.replaceState`, POSTs it, and sets `Referrer-Policy: no-referrer`.

**Passwords**
- Hashed with argon2id via the argon2-cffi `PasswordHasher` defaults (RFC 9106 low-memory profile). Hashing runs in a threadpool behind a semaphore of 4 because each hash uses about 64 MiB. Hashes are upgraded on login when `check_needs_rehash` says so.
- Policy: length 12–256, no composition rules. Reject passwords in a bundled common-password list and passwords containing the email local part or company name.

**Login algorithm**
1. Check rate limits: `ip` 30 per 10 min and `email_hmac` 10 per 10 min. If exceeded, return 429 with the generic message.
2. Look up the user. If the user is missing, has no hash or is locked, verify against a dummy hash so timing stays uniform.
3. On failure: increment `failed_login_count`. At 5 failures, set `locked_until = now + 15 min × 2^lock_count` (capped at 4 h) and increment `lock_count`.
4. Return the same message for every failure: wrong password, locked, inactive or no membership.
5. On success: reset the counters and choose the session stage:
   - `mfa_pending` if a TOTP factor is confirmed;
   - `mfa_enrollment_required` if any effective permission has `requires_mfa` and no factor exists (only enrolment endpoints are allowed);
   - otherwise `active`.
6. Write an `auth_attempt` row and an audit entry (`auth.login.succeeded|failed|locked`).

**MFA (TOTP)**
- 160-bit secret generated with pyotp, encrypted with AES-GCM using the `LK_DATA_ENCRYPTION_KEYS` keyring (`kid:key`, supports rotation).
- `valid_window=1`. Replay is rejected when `step ≤ last_used_step`. Five attempts are allowed per pending session, then it is revoked.
- Ten recovery codes, HMAC-hashed, shown once.
- MFA is required for privileged permissions (`identity.*.manage`, sensitive `org.settings.*`, `system.audit.read`, `system.backup.manage`). The `security.mfa.required_for` setting accepts `privileged|all`.
- Step-up re-authentication (`POST /auth/reauth`, password or TOTP) sets `recent_auth_at`. It is required by permissions flagged `requires_recent_auth`.

**Invitations**
- An admin invites a user. This creates `app_user(invited)`, a membership with roles, branches and teams, and an invitation.
- Issue-on-send: the email job creates the token and stores its hash, so the plaintext token never sits in a job payload.
- If email is not configured (`LK_EMAIL_MODE=demo`), the admin sees a manual link once, labelled "Email delivery: Demo, not sent".
- Tokens expire after 7 days, are single-use, and are revoked by resend or revoke.
- Acceptance sets the password, activates the user, logs them in, and may route to MFA enrolment.

**Password reset**
- Self-service: `request` always returns 202 and sends email only when email is configured. Token lifetime 30 min.
- Admin-issued: a one-time link valid 24 h, shown once. Temporary passwords are never generated.
- Completing a reset invalidates other reset tokens, revokes all sessions, keeps MFA, and emits `identity.user.credentials_changed`.

**Deactivation**
- Sets membership `deactivated`. In the same transaction it revokes sessions, invitations and resets, and emits `identity.membership.deactivated`. The channel subsystem unlinks WhatsApp in response.
- Optional `reassign_to`: modules register `OwnershipProvider`s (count and reassign open owned records) that run in the same transaction.
- Attribution survives. Deactivated users display as "Name (inactive)". Reactivation is supported.

**Profile and self-service:** profile, preferences, password change (current password required; revokes other sessions by default), session list and revocation, MFA enrolment and removal (removal blocked when MFA is required), own delegations and absences.

**First-admin setup CLI.** The app never bootstraps users or resets passwords at startup.
- `lk setup init-company --company-key crown --legal-name … --tz Asia/Kolkata` creates the company, head branch, system role templates and default sequences/settings.
- `lk setup first-admin --company crown --email … --name …`:
  - Refuses (exit code 3) if the company already has an active membership with `identity.role.manage@company`.
  - Default mode prints a one-time setup link (`first_admin_setup`, valid 30 min). `--prompt-password` uses `getpass` twice instead.
  - Never reads a password from arguments or environment variables.
  - Forces MFA enrolment at first login. Writes an audit entry with `actor_type=cli`.
- `--break-glass --reason …` handles admin recovery. It requires the operator to type the company key, issues a reset link for an existing admin, and records a critical audit entry.

## 5. Authorization
**Permission grammar:** `<module>.<resource>.<action>`, for example `sales.quote.update`. This refines the shared `<module>.<action>` convention. Scopes are ordered `own < team < branch < company`. Each permission's allowed scopes are declared in code in `PermissionDef`s and synced to `permission` at startup. Non-record permissions only allow `company`.

**The 14 legacy permissions all map to new keys.** The `legacy_alias` column records the mapping, and migration expands legacy overrides through it.

| Legacy | New |
|---|---|
| view_all_quotes / view_own_quotes | `sales.quote.read@company` / `@own` |
| create_quotes | `sales.quote.create` |
| edit_all_quotes / edit_own_quotes | `sales.quote.update` + `sales.quote.transition` @company / @own |
| delete_quotes | `sales.quote.delete` (draft-only rule in the service) |
| override_price | `sales.quote.override_price` (scope bounded by update scope) |
| export_quotes | `sales.quote.export` (rows bounded by read scope) |
| view_products / edit_products | `catalogue.product.read` / `catalogue.product.{create,update,archive}` + `catalogue.media.manage` |
| manage_users | `identity.user.manage` + `identity.role.manage` + `identity.permission.manage` |
| import_data | `imports.job.run` |
| view_costing | `catalogue.costing.read` (field guard; also covers custom-product costing) |
| manage_categories | `catalogue.taxonomy.manage` |

New keys for modules that were open to any login: `ops.challan.*`, `production.cut_plan.*`, `search.global.use`. Notes and activity derive access from their parent record (below).

**Role templates**
- System templates are read-only rows per company. Modules contribute their grants through `TEMPLATE_GRANTS`.
- `employee` is the base and is inherited by all: directory read, company read, non-sensitive settings read, file upload, own delegation, global search, and own tasks/briefing (keys owned by the tasks module).
- `admin`: every permission at its maximum scope. MFA required.
- `management`, `sales` and `operations` reproduce legacy table 3.2 exactly. Operations keeps legacy company-wide quote read and gains challan and cut-plan permissions.
- `finance`, `production`, `procurement`, `warehouse` and `catalogue` templates hold their module grants.
- Customisation means creating a custom role that inherits a template and adds grants or `deny` entries.

**Role validation**
- Keys and names must be valid. Every permission must exist and its scope must be in `allowed_scopes`.
- Inheritance stays within the same company, has no cycles (checked with a recursive CTE) and is at most 4 levels deep.
- Templates are immutable. A role cannot be archived while assigned. A membership must have at least one role.
- No escalation: an actor can only grant what they hold, at no more than their own scope, and cannot add to their own roles or overrides.
- Last-admin guard: at least one active, MFA-enrolled membership must keep `identity.role.manage@company`.
- Changes to roles, overrides, memberships, teams or delegations increment `company.authz_epoch` in the same transaction.

**Resolution** (cached per `(membership_id, authz_epoch)`; the epoch is read with the session on every request)
1. If the membership is not active, the result is empty.
2. For each role, walk the chain from root to leaf. A grant raises the key to the higher scope. A `deny` in a descendant removes a key inherited from that role's own ancestors.
3. Union across roles, taking the maximum scope.
4. Apply unexpired user grants (maximum scope).
5. Remove every key with a user revoke. **Revoke always wins.**
6. Add active delegations: `delegated[key] = {delegator user ids}`. Only keys that are delegable and that the delegator currently holds count. The cache expires at the next delegation boundary.

**ActorContext** (frozen):
- `actor_type, user_id, membership_id, company_id`
- `branch_ids, team_peer_user_ids, permissions{key: scope}, delegated{key: set}`
- `session_id, auth_strength password|mfa|channel_linked|system, recent_auth_at`
- `channel, correlation_id, request_id, locale, time_zone, authz_epoch, idempotency_key, agent_run_id`

Agents act as their user and never with more authority. `channel_linked` contexts cannot use `requires_recent_auth` permissions. Jobs rebuild the context at execution from stored IDs, so a revocation applies; a job whose actor has been deactivated fails permanently. Per-user outputs such as briefings are always computed with that user's context, never a system context.

**ResourcePolicy registry** (in each module's `policies.py`): `resource_type, model, permission_prefix, owner_columns (e.g. owner_user_id, assignee_user_id), branch_column, parent=(resource_type, fk, action_map), attachment_role_actions, note_write_action='update', actions(ctx, obj) -> {action: Decision(allowed, reason_code)}`. Detail DTOs include `_actions`, so the UI shows only real controls and services enforce the same decisions.

**Scope clause** (`scope_clause(ctx, policy, action)`):
- Always `company_id = ctx.company`.
- `company`: no further filter.
- `branch`: `branch_id IN ctx.branch_ids` OR own OR delegated.
- `team`: an owner column `IN team_peers` OR own OR delegated.
- `own`: an owner column equals the actor, OR an owner column is in the delegators for that key.
- No scope and no delegation: `false()`.

**Children:** `fk IN (SELECT parent.id WHERE scope_clause(parent, action_map[action]))`. Lines, revisions and status history use this.

**Polymorphic children** (notes, attachments, activity, history): `OR` over registered types of `(resource_type = t AND resource_id IN visible_ids(t, action))`. Children are never authorised by their own columns.

**ScopedRepository** (from `uow.repo(Model)`): `get(id, action)` returns 404 if the record is not readable and 403 if it is readable but the action is not permitted. It also provides `select(action)`, `list`, `count`, `exists` and `search(text)` using `escape_like` + ILIKE/trigram; regex is never built from user input. Archived rows are excluded unless asked for.

**Field redaction**
- DTO fields are marked `Annotated[..., Restricted("catalogue.costing.read")]`.
- `redact(dto, ctx)` walks nested models, nulls restricted fields and fills `redacted_fields`. Commands reject writes to restricted fields without the matching write guard.
- `@command` and `@query` apply redaction, so UI, exports, PDFs, notifications, idempotency replays and agent tool outputs all receive redacted DTOs.
- Search documents never index restricted fields. Settings masking uses the same mechanism.

**Making bypass structurally hard**
1. Service functions are decorated with `@command(permission, idempotent=…, actor_types=…)` or `@query`. The decorator opens the UoW, sets the RLS GUCs and actor, checks coarse permissions, MFA and recent-auth, and redacts output. The UoW exposes repositories, not the raw `Session`; `uow.system_session(reason)` is allowed only in allowlisted platform files.
2. Every route must declare `public`, `self`, or `x-resource` plus a permission, or startup fails.
3. Architecture tests (AST):
   - routers import no `sqlalchemy` and no `models`;
   - every public function in `service.py` is decorated;
   - no raw `Session`, `text(` or regex operators appear in modules;
   - no `Query` parameter is named token or auth;
   - tool input schemas contain no identity fields (user_id, company_id, role, permission).
4. RLS backs up company isolation if a code filter is ever missed. Composite foreign keys block cross-tenant references.
5. A route matrix and canary tests prove all of the above (see §16).

| Access path | Enforcement |
|---|---|
| Detail/list/aggregate/count | ScopedRepository; aggregates only over scoped selects |
| Child line, revision, status history | parent policy via child clause |
| Duplicate | source `read` + target `create`; copies through the service |
| Export CSV/PDF | `export` permission + read-scoped rows + redaction + csvsafe |
| Media download | attachment parent `read` (or `export` for generated documents) + classification guard |
| Note / activity / history | polymorphic parent visibility; note writes need parent `update` |
| Search | providers built on repository `search`; per-group counts are scoped |
| Agent tool | same services; context injected; tool matrix test |

## 6. Unit of work, idempotency, events, jobs
- **UoW:** one transaction per command. It commits before the response is returned, so a 2xx means committed. `uow.emit(event)` writes `domain_event` in the same transaction. An automatic `before_flush` audit diff runs for `__audited__` models, excluding hash/secret columns and listing restricted fields.
- **Idempotency** (`Idempotency-Key` header, or derived by the agent runtime; required on execute/convert/post/send commands):
  1. Inside the business transaction, `INSERT idempotency_key … ON CONFLICT DO NOTHING RETURNING`. A concurrent duplicate blocks on the conflicting transaction.
  2. If no row is returned, load the stored row. If `request_hash` differs, return 422 `idempotency_key_reused`. Otherwise, provided the actor still holds the operation permission, replay the stored redacted response with `Idempotent-Replayed: true`.
  3. The response body is saved before commit. Rows expire after 48 h.
- **Outbox relay** (worker loop, every 0.5 s):
  1. `SELECT … WHERE dispatched_at IS NULL ORDER BY seq LIMIT 100 FOR UPDATE SKIP LOCKED`.
  2. For each event and each subscribed handler, insert a job `event.handle` with `dedupe_key='evt:{id}:{handler}'` (`ON CONFLICT DO NOTHING`).
  3. Set `dispatched_at` and commit.
  - There is no global ordering guarantee. Handlers are idempotent and compare `aggregate_version`.
- **Job claim:**
  ```sql
  UPDATE job SET status='running', locked_by=:w, locked_at=now(), lease_expires_at=now()+:lease, attempts=attempts+1, started_at=now()
  WHERE id IN (SELECT id FROM job WHERE status='queued' AND run_at<=now() AND queue=ANY(:q)
               ORDER BY priority DESC, run_at, id LIMIT :n FOR UPDATE SKIP LOCKED) RETURNING *
  ```
  - Each handler runs in its own transaction and ends with a fence: `UPDATE job SET status='succeeded' … WHERE id=:id AND locked_by=:w AND status='running'`. If no row is updated, a `LeaseLost` error rolls back the handler's effects, so database side effects happen exactly once.
  - Long jobs heartbeat every lease/3. Batch jobs fence-check on every batch commit.
  - Retryable errors are requeued with backoff `min(10 s·2^attempt, 1 h) ± 20%` and become `dead` once `max_attempts` is reached. Permanent errors (validation, authorization, not found) become `failed`.
  - The reaper requeues expired leases.
  - Cancellation: a queued job becomes `cancelled` immediately. A running job gets `cancel_requested_at`, which `jc.check_cancelled()` observes.
  - Dead-lettering emits `system.job.dead_lettered`, except for handlers of `system.job.*` events, to avoid loops.
- **Scheduler** (every 15 s):
  1. Lock due schedules with SKIP LOCKED.
  2. Enqueue with `dedupe_key='sched:{id}:{slot}'`, coalescing missed slots.
  3. Compute the next run with zoneinfo and the weekday mask.
- **Worker:** `lk worker --queues default,events,documents,imports,channels,ai --concurrency 4`. Thread pool, adaptive polling every 0.5–2 s (no LISTEN/NOTIFY), heartbeat every 10 s. Graceful shutdown: stop claiming, wait 30 s, release leases.
- **Platform job kinds:** `event.handle`, `identity.send_invitation_email`, `identity.send_reset_email`, `files.generate_variants`, `system.cleanup` (hourly), `system.integration_healthcheck`, `system.backup.nightly` and `system.restore_rehearsal.weekly` (both disabled in dev).
- **`system.cleanup` removes:** expired sessions, auth attempts older than 90 days, rate-limit windows older than 1 day, expired idempotency rows, succeeded jobs older than 14 days, failed/dead jobs older than 90 days, unattached files older than 24 h, and expired exports.

## 7. Document numbering
- **Defaults:** `sales.quote` `{brand}-QT-{yyyy}-{seq:04}` yearly; `ops.challan` `DC-{yyyy}-{seq:04}` yearly; `sales.custom_product` `CP-{seq:04}` never. Brand tokens match `^[A-Z]{2,4}$`. One counter per company per key is shared across brands, so numbers never collide.
- **Allocation**, called late in the business transaction:
  1. `period_key` is the local year of the document date in the sequence's zone (Asia/Kolkata), or `all` for never-reset sequences.
  2. Allocate:
     ```sql
     INSERT INTO document_sequence_counter(sequence_id,company_id,period_key,next_value) VALUES(:s,:c,:p,:start+1)
     ON CONFLICT(sequence_id,period_key) DO UPDATE SET next_value=document_sequence_counter.next_value+1 RETURNING next_value-1
     ```
  3. Format the number and insert into `issued_document_number` with `ON CONFLICT DO NOTHING RETURNING`. If it collides, retry up to 3 times, then raise `SequenceCollision`, which logs an alert.
  - A rollback consumes nothing. Voided documents keep their number, and numbers are never reused.
- **Settings validation:**
  - the format must contain `{seq:N}`;
  - `yearly` requires `{yyyy}` or `{yy}`;
  - `next_value` may only increase;
  - a preview endpoint shows the next number without allocating it.
- **Migration:** `lk sequences reconcile` registers legacy numbers and sets each counter to max + 1.

## 9. Files
- **Storage interface:** `StorageBackend{put_stream, open_stream, head, delete}`. Implementations: `LocalFsStorage` (`var/storage`, dev default) and `S3Storage` (boto3; any S3-compatible endpoint, SeaweedFS in compose).
- **Upload** (`POST /api/files`, multipart, rate-limited):
  1. Stream to a temp file with per-purpose size limits (images 15 MB, documents 25 MB, imports 50 MB) while computing SHA-256.
  2. Sniff magic bytes: JPEG, PNG, GIF, WebP (verified with Pillow), PDF, OOXML zip, OLE doc/xls, UTF-8 CSV/text.
  3. Reject SVG, and reject any extension that disagrees with the sniffed type.
  4. Dedupe on `(company, sha256, purpose)` and store.
  - Unattached files are visible only to the uploader for 24 h. Attaching requires parent `update` and the same uploader, which is how upload ownership is enforced.
- **Download** (`GET /api/files/{id}/content?variant=`, cookie auth, streamed through the backend):
  - Authorisation via attachment parents (or creator-only for exports, any member for branding).
  - Headers: `nosniff`, `CSP: sandbox`, RFC 6266 `filename*`, `inline` only for images and PDFs, `private` cache with ETag (`no-store` when restricted).
  - Restricted and generated-document downloads are audited.
- No presigned URLs. Image variants (`thumb_256`, `preview_1024`) are generated by a job and stripped of EXIF.

## 12. Observability
- **structlog**: JSON in production, console in dev. Context variables: request_id, correlation_id, user_id, company_id, job_id.

## Decisions
- **Server-side opaque sessions in an HttpOnly, SameSite=Lax cookie (__Host- prefix in production), SHA-256 token hash in auth_session, instead of JWT** — Instant revocation on deactivation, logout, password or permission change without a denylist. Not readable by XSS. No refresh-token machinery. The per-request indexed lookup is negligible at internal scale. Fixes legacy 24 h unrevocable JWTs.
- **Same-origin topology (Next rewrites in dev, reverse proxy in production), no CORS; CSRF via synchronizer token header plus Origin check** — Cookies work for plain <a href> downloads, so tokens never go in query strings. Removes the legacy CORS '*' with credentials.
- **argon2id via argon2-cffi defaults (RFC 9106 low-memory) in a threadpool behind a semaphore of 4; NIST-style length plus common-list policy; lockout with exponential backoff plus IP/email rate limits stored in Postgres** — Maintained library with a current recommended profile. The semaphore bounds the 64 MiB-per-hash memory. No Redis dependency. Generic errors prevent user enumeration.
- **TOTP MFA (pyotp) with AES-GCM-encrypted secrets, replay protection by step, recovery codes; required for privileged permissions; recent-auth step-up for critical actions** — Meets the administrator MFA requirement without external providers. Step-up covers role, permission, bank and backup changes.
- **No startup bootstrap. A one-time first-admin CLI (setup link by default, getpass optional) that refuses when an admin exists; break-glass is audited** — Removes the legacy fixed bootstrap credential and the password reset that ran on every boot. Credentials never pass through args or env.
- **Permission key grammar <module>.<resource>.<action> plus scope {own<team<branch<company}; catalog defined in code and synced to DB; 14 legacy permissions mapped via legacy_alias** — Refines the shared '<module>.<action>' convention so multi-resource modules are unambiguous. Startup validation keeps templates, routes and modules consistent.
- **System role templates are read-only. Customisation is by inheriting roles with grant/deny (deny only affects that role's own chain). User overrides grant or revoke, and revoke always wins. Anti-escalation and last-admin guard apply** — Upgrades can evolve templates safely. Inheritable finance/production/procurement/warehouse/catalogue templates. Matches the revoke-precedence requirement.
- **Central ScopedRepository plus ResourcePolicy registry; child and polymorphic objects (lines, revisions, notes, attachments, activity, history) are authorised only via their parent; 404 when not visible, 403 when visible but forbidden** — One predicate builder for every read path (detail, list, search, export, download, tools) makes IDOR fixes structural. 404 avoids existence leaks.
- **Postgres RLS on company_id (fail-closed via NULLIF GUC) plus composite tenant foreign keys, as defense in depth; record-level scopes stay in the application** — Company isolation holds even if a code path forgets a filter. The cost is low: one transaction-local set_config. App-level scopes stay simple to test.
- **Sync SQLAlchemy 2.x with psycopg3 and def endpoints; @command/@query service decorators own the transaction, idempotency, permission check and redaction** — The same unit-of-work semantics apply to UI endpoints, agent tools and jobs. Avoids async-ORM pitfalls. The commit happens before the response is returned, so 2xx means committed.
- **Field redaction at the DTO boundary via Restricted(permission) annotations, applied by the service decorators; logs redacted separately by a structlog processor** — UI, exports, PDFs, notifications, idempotency replays and model context all get identical redaction (scenario E). Fixes legacy costing leaks.
- **Outbox = domain_event table; the relay fans out to per-handler jobs with dedupe keys; handler effects commit atomically with a fenced job completion** — Exactly-once database effects per handler despite redelivery or lease expiry (scenario I) with no message broker.
- **Postgres job queue with FOR UPDATE SKIP LOCKED, leases, heartbeats, backoff, cooperative cancellation and simple interval/daily schedules; polling, no LISTEN/NOTIFY, no cron library** — Durable and monitorable using the existing database. Fits a small worker. Avoids Celery/Redis and speculative infrastructure.
- **Idempotency rows inserted inside the business transaction, storing the redacted response; mismatched request hash returns 422** — No stuck in-progress states. Concurrent duplicates serialise on the unique conflict. Replays honour current permissions.
- **Numbering by counter upsert inside the business transaction plus an issued_document_number registry; yearly reset requires a year token; counters can only increase** — Atomic, gapless on rollback and never reused, even after config changes or migration. Fixes legacy races and count+1 collisions while preserving the LK-QT-YYYY-NNNN, DC-YYYY-NNNN and CP-NNNN formats.
- **Defaults: quote and challan sequences reset yearly, CP never; period year computed in Asia/Kolkata** — The legacy quote counter's failure to reset was listed as a defect. Formats with a year token make yearly reset safe. Local year avoids UTC boundary errors around New Year.
- **Typed settings registry (Pydantic schema, read/write permission, masking) with setting_revision history** — Company identity, GSTIN, bank details and terms become permission-protected, versioned data. Issued documents can reference the exact terms version.
- **Authenticated downloads streamed through the backend, with no presigned URLs; SHA-256 dedupe; magic-byte sniffing; no SVG; object keys never derived from filenames** — Complies with the no-tokens-in-URLs rule and authorises every download by parent visibility. Re-imports do not duplicate media.
- **Python 3.12 with an app-generated UUIDv7; PostgreSQL 16 feature baseline** — pgserver (the no-Docker fallback) ships wheels only up to CPython 3.12 with PG 16.2. Python 3.12 is installed on the machine. A 10-line RFC 9562 generator avoids an extra dependency.
- **Local dev: one npm run dev command; Docker compose postgres:16 when the daemon is reachable, otherwise a supervised pgserver plus local FS storage; SeaweedFS (optional profile) for S3 testing; moto in tests** — Works on this machine with Docker stopped. MinIO community images are no longer published, so SeaweedFS is used instead.
- **Demo seed creates passwordless fictional users in an is_demo company; access via one-time sign-in links; demo reset limited to is_demo companies** — No fixed or published demo passwords. Isolated demo dataset per the import/clear-sample requirement.
- **Users are never hard-deleted; membership deactivation revokes sessions and tokens in the same transaction and emits an event for channel unlink** — Preserves historical attribution. Gives immediate revocation across web and WhatsApp.
- **Backups via pg_dump -Fc plus object manifest, with an automated restore rehearsal into a temporary database that verifies counts, revision, RLS and checksums** — Proves the documented path locally (scenario M) without managed infrastructure. Production should add PITR.
- **Platform kernel modules live under app/platform/<name> with the same file layout as domain modules under app/modules/<name>** — Import direction (core -> platform -> modules) is enforceable by an architecture test while keeping the shared file convention.

## Risks
- pgserver 0.1.4 has not been released since June 2024 and may lack pg_dump/pg_restore or contrib extensions (pg_trgm) on Windows. Mitigation: Docker is the primary path; backup binary lookup falls back to PATH and docker exec; the trigram migration is conditional. Verify in slice 1.
- RLS adds operational subtlety: worker jobs must set the company GUC per job, and cross-company platform tables must be explicitly exempt. Forgetting the GUC fails closed (empty results), which can look like data loss. Mitigation: a UoW-only GUC setter plus integration tests that run as lk_app.
- A single counter row per sequence serialises document creation per company, and long business transactions holding the lock block others. Mitigation: allocate late in the transaction; keep transactions short.
- Sync SQLAlchemy uses the AnyIO threadpool (about 40 threads). Long AI streaming or file-proxy requests must not hold DB sessions or exhaust threads. Mitigation: stream without an open transaction and size pools explicitly.
- argon2 memory cost (about 64 MiB per hash) under a login burst. Mitigation: the semaphore plus rate limits.
- Using Next rewrites as the production proxy hides client IPs and weakens IP rate limits unless trusted proxy headers are configured. Mitigation: recommend a reverse proxy; set LK_TRUSTED_PROXY_IPS.
- Losing LK_DATA_ENCRYPTION_KEYS makes TOTP secrets unrecoverable. Mitigation: the runbook requires separate key backup; recovery is forced MFA re-enrolment.
- Without SMTP configured, self-service password reset is unavailable, and admin-issued links depend on out-of-band sharing.
- Polymorphic parent-visibility subqueries for notes, activity and history may be slow as data grows. Mitigation: composite indexes on (company_id, resource_type, resource_id) and per-type visible-id subqueries; measure in slice 2.
- The IDOR route matrix requires a factory for every resource type. The coverage test enforces this but adds maintenance cost for every module designer.
- Windows process-tree management and signals in dev.mjs and the worker (no SIGTERM). Mitigation: taskkill /T and KeyboardInterrupt handling, tested on this machine.
- SeaweedFS S3 compatibility gaps versus AWS. Mitigation: the adapter sticks to basic put/get/head/delete and is contract-tested with moto; SeaweedFS is optional in dev.
- Other subsystem designers may assume a two-segment '<module>.<action>' permission key. The platform's three-segment grammar must be propagated, and startup validation will reject mismatches.
